## Context
Newsly is my AI news-intelligence app (Next.js, Prisma + Postgres/pgvector, Inngest, SerpApi, Firecrawl, OpenAI).
Pipeline: candidate URLs → dedupe → story clustering → Firecrawl full content → AI evaluation
(impact, novelty, financial significance) → score → rank → Top N India + Top N World → AI summary.

## Problem
When I ask for 5 stories I often get 1–2. That can't be right — there is always more news.
Either (a) too few candidates are coming in, or (b) the AI evaluation/filters are too strict, or both.

## Step 1 — Diagnose before changing anything
Add logging that prints a funnel count per run, per region:
  fetched → after dedupe → after clustering → after Firecrawl (success/fail) → after AI eval → passed threshold → returned
Run it a few times for India and World and show me the numbers.
Tell me where most candidates are lost, and what each filter/threshold is (file + line).

## Step 2 — Add more sources (max 5 extra per region)
Add these as new source clients, using the same interface as the existing ones:
- India: https://www.livemint.com/news/india plus up to 4 more top Indian business/financial outlets
  (e.g. Economic Times, Moneycontrol, Business Standard, The Hindu BusinessLine)
- World: https://www.livemint.com/news/world plus up to 4 more top global outlets
  (e.g. Reuters, CNBC, BBC Business, Al Jazeera)
Rules:
- Prefer each site's RSS feed over scraping the HTML page. Find and verify the real feed URLs; don't guess.
  Fall back to Firecrawl only if a site has no usable feed.
- Skip sites behind hard paywalls or that block bots.
- Pick sources by region from a config (region → list of sources), so I can add/remove sources without code changes.
- Normalise every source to the same candidate shape (title, url, source, publishedAt, snippet, region).
- Only keep items from the requested time window (day/week/month).

## Step 3 — Loosen the selection so N stories always come back
- Change from "pass/fail against a fixed score threshold" to "rank everything, return the top N".
- Keep a low floor only to drop clear junk (ads, duplicates, non-news, irrelevant).
- If fewer than N pass the floor, backfill with the next-best ranked stories rather than returning fewer.
- Review the evaluation prompt: it should score relative importance, not ask "is this significant enough?"
  Show me the old vs new prompt.
- Make sure clustering isn't merging unrelated stories into one (check the similarity threshold).
- Return fewer than N only if there are genuinely fewer than N valid candidates, and log why.

## Latency constraints (important)
Total run time should not increase noticeably.
- Fetch all sources in parallel with a per-source timeout (~5s); a slow or failing source is skipped, not awaited.
- Cache source fetches for a few minutes.
- Run Firecrawl only on the shortlisted candidates (e.g. top 2–3× N after a cheap pre-rank on title/snippet),
  not on everything fetched.
- Batch the AI evaluation calls where possible.
- Report run time before vs after.

## Done when
- Asking for 5 India and 5 World stories reliably returns 5 each.
- The funnel log shows where candidates drop.
- Latency stays within ~20% of the current run time.
- Summarise what you changed and why, with the before/after funnel numbers.
