## Pro-only access (applies to every step below)
The public API is a **Pro feature**. Pro is checked in two places — when a key is created **and on every
request** — so a user who cancels Pro can't keep using the API.

```
 Free user  → Developers page shows an upgrade card; "Create key" disabled; docs stay public
 Pro user   → create keys, call the API with Pro limits
 Pro → Free → keys kept but suspended: every call → 403 plan_required
 Re-upgrade → the same keys work again (no re-integration needed)
```

- **Single source of truth:** `lib/billing/plan.ts` exporting `getUserPlan(userId): Promise<"free" | "pro">`,
  reading whatever plan system Step 0 found (default `"free"`). Every check below uses only this function.
- **Plan cache:** cache the plan per user for 60s (Redis if available, else an in-memory LRU) so API requests
  don't hit billing each time. Invalidate immediately on billing webhooks / plan-change events if they exist.
- **Limits by plan** in one config, `lib/api/v1/limits.ts`, env-overridable, structured for future tiers
  (e.g. `business`):
  `pro: { requestsPerMinute: 60, pipelineJobsPerDay: 50, maxActiveKeys: 10 }`.
- **Downgrade / cancel:** keys are not deleted. They stay listed as "Suspended — Pro required" and resume
  automatically on re-subscribe. Revoke always works.

## Step 1 — API keys

**Data model (Prisma, new migration)**
```
ApiKey
  id            uuid
  userId        → User (onDelete: Cascade)
  name          string            // user-given label, e.g. "Trading bot"
  prefix        string  @unique   // first 12 chars shown in UI, e.g. "ds_live_a1B2"
  hashedKey     string  @unique   // SHA-256 of the full key (hex); full key is NEVER stored
  scopes        string[]          // e.g. ["news:read","news:write","research:write","newsletters:write"]
  lastUsedAt    DateTime?
  expiresAt     DateTime?         // optional, user-chosen (30/90/365 days or never)
  revokedAt     DateTime?
  createdAt     DateTime

ApiRequestLog                     // for usage page, quotas and debugging
  id, apiKeyId, userId, method, path, status, durationMs, costClass, requestId, createdAt
  @@index([apiKeyId, createdAt])
```

**Key format:** `ds_live_` + 32 random bytes base62 (crypto.randomBytes). Show the full key **once** at creation;
store only the SHA-256 hash. Lookup = hash the presented key → find by `hashedKey`.

**Rules:** creating a key requires Pro (checked in the server action, never only in the UI); max active keys
per user from `limits.ts` (Pro: 10); revoking is immediate; expired/revoked keys return 401;
update `lastUsedAt` at most once per minute per key (avoid a DB write on every request); never log the full
key anywhere (logs, Neatlogs, errors).

**Scopes**
| Scope | Allows |
|---|---|
| `news:read` | public stories, own briefing results |
| `news:write` | create news briefings |
| `research:read` / `research:write` | read / create stock research reports |
| `instruments:read` | instrument search |
| `newsletters:read` / `newsletters:write` | list / create, update, pause, delete newsletters |

## Step 2 — Request pipeline (one shared wrapper for every v1 route)
Create `lib/api/v1/handler.ts` exporting `apiRoute({ scope, costClass, input, output }, handler)` that does,
in order:
1. **Request id** — generate `req_…`, return it as `X-Request-Id` on every response.
2. **Auth** — read `Authorization: Bearer <key>`; 401 if missing/invalid/revoked/expired.
3. **Plan** — `getUserPlan(key owner)` (cached). Not Pro → 403 `plan_required`:
   `"The Dainik Samachar API requires an active Pro plan."` Then 403 `forbidden` if the scope is missing.
4. **Rate limit** — per key, sliding window, limit from `limits.ts` (Pro: 60 requests/min). Headers on every response:
   `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`; 429 with `Retry-After` when exceeded.
5. **Quota** for expensive endpoints (costClass `pipeline`): per user per day, from `limits.ts`
   (Pro: 50, env-overridable). 429 code `quota_exceeded` when used up. Count only accepted jobs.
6. **Validation** — zod for query, params and JSON body (reject unknown fields; max body 64 KB). 400 with
   field-level details.
7. **Idempotency** — for POSTs that start pipelines, honour an optional `Idempotency-Key` header: same key +
   same user within 24h returns the original response instead of starting a second job.
8. **Tracing** — wrap in the existing Neatlogs `runWorkflow` with endUserId = key owner, `source: "api"`,
   metadata `{ apiKeyId, requestId, plan }` (never the key itself).
9. **Logging** — write ApiRequestLog (status, duration, cost class).
10. **Errors** — every error uses one shape (below); unexpected errors return 500 `internal_error` with the
   request id, never stack traces or provider messages.

**Clerk middleware:** make `/api/v1/*` public to Clerk (the API-key wrapper does auth instead), but keep every
other route's protection exactly as it is. **CORS:** no browser CORS by default (server-to-server API); document
that keys must never be used in front-end code.

**Response conventions**
- JSON, `camelCase`, ISO-8601 UTC timestamps, IDs as strings.
- Success: `{ "data": … }` (lists add `"pagination": { "nextCursor": string|null }`).
- Error: `{ "error": { "code": "invalid_request", "message": "…", "details": [{ "field": "storyCount", "issue": "…" }], "requestId": "req_…" } }`
- Error codes: `invalid_request` 400, `unauthorized` 401, `plan_required` 403, `forbidden` 403 (missing
  scope), `not_found` 404, `conflict` 409,
  `rate_limited` 429, `quota_exceeded` 429, `internal_error` 500, `upstream_unavailable` 503.
- Pagination: cursor-based, `limit` 1–50 (default 20).
- Ownership: a key only ever sees its owner's briefings, reports and newsletters (404, not 403, for others').
  Public stories are readable by any key with `news:read`.
